# 玩家角色三维资产验收工具

工具和依赖全部位于本目录，不修改游戏 `src/`、根 `package.json` 或根 lockfile。固定使用 `three@0.187.0`，版本查询记录见 `dependency-record.json`，完整锁定见本目录 `package-lock.json`。

## 打开

可以直接双击 `dist/viewer.html`，通过“选择角色 GLB”读取本机文件；页面与 Three.js 代码已完整内嵌，无 CDN。动作 GLB 可多选添加。

也可以在本目录执行 `node serve.mjs` 后打开 <http://127.0.0.1:5188/>。正式玩家使用 <http://127.0.0.1:5188/?asset=/hero.glb&yaw=225>，固定只读路由直接读取原文件，没有重复拷贝。`yaw` 只改变预览朝向，不修改资产。指定 `?asset=/assets/hero.glb` 可自动打开本目录中对应文件。`?probe=1` 只载入现有机器人**静态技术探针**，明确显示无骨架/无动画，不是最终玩家。默认页面不载入任何通用角色。

## 使用

1. 导入完整、贴图内嵌的角色 GLB。检查真实面数、蒙皮、关节、贴图与动画轨道。
2. 切换文件实际包含的动画。过渡使用官方 `AnimationMixer` / `AnimationAction.crossFadeTo`。支持暂停、真实单帧、时间轴精确定位、骨架显示与播放速度。时间轴拖动会暂停并清除其他动画权重，只显示指定片段的真实姿态。
3. 开启连续 360° 转向，以固定 46° 正交俯视或自由相机检查正侧背面。移动预览只移动地面，不生成骨骼动画。
4. 如有分开的动作文件，添加带完整同骨架/绑定数据的动画 GLB。严格比较关节名称、父级和每个关节的 inverse bind matrix；无法安全映射的目标、重名节点或不同骨架会明确拒绝，不做自动重定向。
5. “合并动作并导出 GLB”使用官方 `GLTFExporter`；保留主角色原始单位与原始比例，并带上真实动画。画面归一化与转向不写入输出。导出后重新导入检查。
6. “录制当前预览（10秒）”使用浏览器标准 `canvas.captureStream()` 与 `MediaRecorder` 录下真实 Three.js 画布并下载 WebM。录制期间可切换真实片段或朝向；不会生成或加工动作。

静态的 `Hold` / `Pose` 片段单列为“保持姿势”，不冒充动态动作。正式文件共 19 个片段，数据检查为 18 个动态动作 + 1 个拉弓保持姿势。

静态模型没有动画会明确报出，禁止用动作名称、模型整体旋转或文件加载成功替代完整角色验收。结构检查不等于动作自然度、风格或武器持握已通过。

## 构建与验证

依赖已安装时执行 `node build.mjs`，使用根工程已有 esbuild 生成单 HTML。启动 server 后执行 `node verify.mjs` 验证空页、静态探针、连续转向、错误拒绝、移动布局和 file:// 独立使用。

`node verify.mjs --animated-fixture` 额外下载 Three.js 官方 `r187` 的 Soldier 模型到 `qa/fixtures/`，仅测试真实骨骼动作、暂停单帧、同骨架合并、不同关节拒绝和 GLB 导出再导入。该第三方模型**仅为工具测试夹具，不是玩家交付资产，也不在默认预览中**。来源与 SHA256 随夹具记录。

结果在 `qa/verification.json`，截图也保存在 `qa/`。正式玩家导入后应另行保存该模型的真实报告和动作录像，不能将夹具测试作为正式玩家验收。
