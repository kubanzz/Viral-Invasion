# Protocol history audit

The original requirements are AC-M08-02 (development acceptance line233: conditions, effects, costs and UI copy agree and have event evidence) and AC-M14-05 (line296: hints agree with real rules; no false safe-window statement).

The frozen v0.7.3 implementation calls `remember(PROTOCOL_CHAIN_HIT, 连锁净化 N 跳)` inside `GrowthController.onKill`, before `GameSession.applyGrowthCommands` applies the selected damage commands. That host can skip a dead/missing target, reject the other organ, or accept zero/partial damage at the mother-core membrane. Resonance and ricochet histories similarly use requested configuration damage. `growthHistoryMarkup` displays the stored text unchanged, and `GrowthVisuals.drawProtocolHits` used planned hit logs without requiring their positive host receipt. Accepted runMetrics/HUD counters already used stricter same-tick/root/target joins.

The fix retains explicit planning information and adds readable actual-effect records from the existing accepted host metrics and exact positive TARGET_HIT. Chain records aggregate unique accepted targets within the root/tick and use actual HP loss, not requested damage. Visual hop acknowledgements require the same host receipt and number only accepted hops. Core damage, target selection, command order, budgets, chain recursion, equipment and configured damage are unchanged.

New tests are isolated mechanism presets, not browser or victory evidence. Direct setup and the command bridge are clearly labelled. Damage receipts come from the unchanged common GameSession host path, including a real protected core membrane. Browser and 1000-session runs are deliberately not launched by this audit. The legacy `activations` telemetry continues to describe attempted activation; it is not presented as actual damage or the accepted combat counters.

AC-M08-03 is interpreted using its literal preset-scene requirement; a full formal campaign is not an extra acceptance condition. `protocol-synergy-repeat.test.ts` supplies two actual InputFrame/cooldown repetitions per pair and both single-protocol controls. Pulse + Chain accepts three neighbor hops on both repetitions, versus two for Chain alone and zero for Pulse alone. Trace + Beacon bites the marked farther target first on both repetitions; Beacon alone bites the nearer unmarked target, and Trace alone retains baseline patrol. Every asserted pair joins a positive real-host TARGET_HIT at the same root/tick. These preset-scene results close AC-M08-03 technically, without claiming a full campaign, browser, blind playtest, or player-fun verdict.
