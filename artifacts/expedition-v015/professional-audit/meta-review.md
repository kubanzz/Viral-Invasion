# v0.15 营地与奖励独立审查

范围：只读代码、最终三次真实输入报告和发布截图。没有启动浏览器、修改生产文件或模拟新玩家。以下优先级是体验与产品判断，不把规则测试通过等同于有趣。

## 1. P1：正常通关跳过了最重要的奖励展示（已证实的表现缺口）

- `src/game/session.ts:1356` 创建掉落，紧接着 `:1369–1385` 在同一更新内满足最后净化条件、自动收齐、暂停显示胜利。
- 最终桌面报告掉落 tick8564、胜利快照 tick8564；最终触控报告掉落 tick14733、胜利快照 tick14733。它们证明正确入库，却不给常规玩家看到地上战利品的渲染窗口。
- `src/ui/territoryHud.ts:163–166` 的胜利页只写“战利品已带回”，没有本局枪型、品质、蓝图和40材料清单。补充 loot 演示必须刻意留一只真实幼体，才拍到袋子。
- 对目标的影响：玩家能完成闭环，却很可能感受不到“掉紫／掉金”的惊喜，也看不出 Boss 带来永久成长。
- 最小改进：保持立即保存与死亡优先规则，在胜利结果里加入可跳过的奖励揭示卡，明确品质、贯脉特性、速装蓝图和材料；提供“去修复这把武器”的直达入口。不要为看掉落强制拖延战斗或增加残敌。

## 2. P1：新枪是有意义的横向选择，但当前缺少可感知的身份（事实＋需试玩验证的感受）

- `src/game/expedition.ts:12–16`：稳流34伤／单体，贯脉28伤／两体；初得紫贯脉为29.68伤，+1为30.52。最高金+3也为33.04，单体仍低于起始34。这个横向取舍合理，不应直接把伤害调高抹平。
- `src/game/playerProjectiles.ts:73–82`：两枪都创建同一种 `primary` 弹体，只改伤害和命中数；`src/render/phaserRenderer.ts:377` 共用持枪图，`src/render/expeditionArt.ts:75–76` 的新枪资产目前主要是 UI 图标。
- `src/game/endlessGrowth.ts:23,45–52`：局内“贯穿净化”也提供同一种额外穿透，稀释新武器独特性。局内一级伤害+18%，大于全部永久增幅上限18%；永久一级+3%的作用难从瞬时手感判断。
- 对目标的影响：玩家可能把紫枪读成伤害降低的旧枪。是否真的发生需新玩家观察，不能凭代码断言。
- 最小改进：保留平衡，给贯脉弹明确短贯穿闪点／连续命中反馈与不同枪口节奏，营地提供两只并排靶子的5秒试枪；比较卡用“单体点杀／贯穿清线”说明用途，而非只比一个伤害数字。不先增加武器数量或更多品质层。

## 3. P2：首通后短期经济可用，但持续复刷目标很快只剩抽品质（已证实的范围，长期留存为假设）

- `src/game/expedition.ts:6–7,16,38–42`：仅2蓝图、2枪型；首通已取得全部蓝图，之后每次固定40材料，重复蓝图再转5。
- `src/meta/campProfile.ts:151–163,177–195`：强化每枪只有3级；修复10、三级合计36，抗体最多2支、每次共10。正常复刷很快能负担全部数值强化。
- 首通40足够修复10、+1花8和两支抗体10，还剩12；三份最终报告均实际走到这组状态。重复材料回收让后续资金更宽裕。
- `src/ui/campHud.ts:30–33`：出击台只有“心脏·再次清剿”，未呈现本次明确的新挑战目标。代码只有新seed，不足以证明玩家愿意第二次玩。
- 最小改进：先用已有感染、筑巢、祭团规则做少量可选心脏委托（例如低心核损伤／更长健康控制／特定精英），把成绩与横向打法作为回玩目标；不先加材料种类、无限强化或新器官来掩盖首关体验。

## 4. P2：第一次回营的“获得→修复→装备→体验”路径仍依赖玩家读菜单（体验假设，有代码依据）

- `src/main.ts:188–199` 首次进入可行走营地，顶部为通用营地菜单、出击和附近设施。`src/ui/campHud.ts:26–37` 仓库与锻造分开，初始概览没有“本次新获贯脉枪待修复”的专用引导。
- 修复按钮只修复，装备按钮在另一个仓库页；`src/meta/campProfile.ts:170–188` 规则正确，但玩家是否理解不是自然自动操作证据能证明的。
- 发布的营地锻造截图显示紫枪+1与数值，但没有与当前稳流枪用途的可操作比较或试射。
- 最小改进：首次回营加一条可跳过的短任务“修复战利品→装备→试射→再次出击”，待修复项目加角标；修复成功卡给“装备并试射”按钮。后续回营不重复打断。

## 已确认的基础与未发现的问题

- 奖励有run级唯一凭证，先暂存后胜利入库、跨刷新放弃未完成战利品、备货一次性消费、装备快照、最高品质收藏与重复转材料均有清晰实现和对应测试。
- `src/main.ts:506` 已专门显示营地奖励保存失败并允许重试；不能误报“结算没提示存储失败”。
- 当前审查没有确认阻断进程或奖励重复的技术缺陷。最值得优先改的是奖励可见性与新武器可感知性。真实复玩率、首通经济满意度与新手菜单理解仍需观察。

建议顺序：奖励揭示与直达修复 → 新枪试射／特性反馈 → 首次回营引导 → 用真人结果决定是否做心脏委托。
