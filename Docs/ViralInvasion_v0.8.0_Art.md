# v0.8.0 美术接入与后续更新

日期：2026-10-28。目标是把持续交付的美术接入同一套可离线运行的游戏，并保持现有战斗规则、碰撞、存档和输入语义。

## 当前接入范围

- Phaser 4.2.1 的 WebGL 场景负责最终画面、图集资源、原生精灵、排序、精灵复用和扫描/治疗帧动画；游戏仍由原有固定时钟和 `GameSession` 决定规则，不启用第二套物理或战斗模拟循环。
- 白蓝医疗机器人、普通/晶壳/潜伏病毒、感染源、组织状态、心脏瓣膜、气道门、肺泡及心脏前景使用选定图片。主菜单独立使用高分辨率角色图，战斗中的角色保留较小图集帧。
- 心脏地面使用手绘原图内部裁片；包含墙面的完整图用于边界外的氛围层。图中墙壁不生成碰撞。肺部使用独立地面与透明远景，保留真实通行区域。
- 角色与设施按脚底锚点排序；图片具有独立可见范围，参与遮挡和文字避让。360° 瞄准与武器反馈保持独立，固定朝向的动作图仅在方向相符时使用。
- 已有危险预警、标签、导航、母巢、裂殖和免疫细胞等程序绘制仍通过兼容 Canvas 图层进入 Phaser。当前不是所有图形都已改写为原生精灵，也不把兼容图层称为新手绘资产。

选材表包含 39 个精灵条目、40 个逻辑 ID（包含别名）、5 个环境条目，共引用 42 个原始文件。选材表中的预留候选、图标或姿态不代表每张图都已用于某个游戏动作。

## 持续更新方式

上游来源默认为 `D:\project\xsj\Viral-Invasion\asserts`；工作区 `asserts/` 保留可独立构建的本地快照。可用环境变量 `VI_ART_SOURCE` 指定另一来源。同步只复制新增或内容变化的文件，不删除本地历史文件，也不修改上游原件。上游目录不存在时使用本地快照；若选中的必需原图在本地也不存在，则构建失败并列出缺失项。

`asserts/art-selection.json` 是游戏选材的权威记录。它把逻辑 ID 绑定到具体文件，定义导出尺寸、脚底锚点、裁片和待补状态。上游文档保留原样，不把格式不一致的历史 CSV 当运行时清单。

- **替换同一路径的已选图片**：下次同步重新计算内容哈希，并重建图集。
- **交付新文件或新批次**：先复制进快照，在 `.art-generated/art-sync-report.json` 的 `unknownCandidates` 中列出；不会按“最新编号”自动替换已验收角色或敌人。
- **历史候选**：已在选材表 `catalogue` 登记，不反复列为未知新素材。新候选完成身份、方向、透明边和实机检查后，再更新逻辑绑定与目录记录。
- **删除上游文件**：本地历史快照保留，报告记录 `missingUpstreamPaths`；不直接删除已经可用的素材。

```sh
node scripts/art-sync.mjs          # 同步并生成图集
node scripts/art-sync.mjs --check  # 只读检查来源与生成物是否一致
npm run dev                       # predev 自动执行一次同步
npm run build                     # prebuild 和构建脚本均保证同步
node scripts/package-release.mjs  # 校验构建来源并生成新版本离线包
```

开发服务启动与正式构建前自动同步。开发服务已经运行时，新增美术后可手动执行 `npm run art:sync`，再重新加载页面。目录持续更新不代表发行包会在玩家机器上读取该目录；发行包固定包含当次已选资产。

## 派生资源与离线发行

Sharp 0.35.5 只执行确定性的透明裁切、缩放、留边与图集排布。原始 PNG、SVG、清单和预览保持原样；没有利用缩放替代修图或补画。

每张图集的长宽不超过 2048。生成物保留原图 SHA256、脚底 `pivot`、可见范围、素材状态和未补内容。状态配对保留同一画布与接地配准。主菜单 `hero.selected` 输出大小设为 512，可见角色高 496 像素；战斗 `hero.idle` 仍使用 256 级导出，可见角色高 240 像素。

当前生成规模：

| 项目 | 数量或体积 |
|---|---:|
| PNG 图集 | 1 张，1998×1718，2,082,223 字节 |
| 图集与环境 PNG 有效数据合计 | 6,669,602 字节 |
| 内嵌运行时 JSON | 8,936,541 字节 |
| `.art-generated/` 所有生成文件合计 | 15,627,075 字节 |

以上是生成资源体积，不是完整 `game.js` 或 ZIP 体积；Phaser、游戏逻辑和构建元数据另计。后续素材变化会使数值变化，以当次生成报告为准。

正式构建把图片和图集描述以 data URI 内嵌到 classic/IIFE `game.js`，保持五文件发行包。运行时不引用上游绝对路径，不需要 CDN、图片服务器或运行时 JSON 请求。`build-meta.json` 记录引擎版本、美术签名、图集体积以及选材、管线脚本和选定原图的哈希；打包前再次核验，拒绝混装旧构建与新素材。发行目录存在时拒绝覆盖。

## 尚未完成的美术与验收边界

- 主角素材以单张关键姿态为主，仍缺真正连续的多方向行走、受击、冲刺与攻击动画；不能把姿态切换、轻微起伏或重复静帧当作完整逐帧制作。
- 部分动作图带有固定方向的光效，仍需制作独立特效层和更多方向。裂殖概念图包含多个个体，未被当作一个身体贴到普通碰撞体上。
- 母巢阶段、裂殖身体、免疫小队和部分战术表现继续使用程序绘制；肺部、节点及设施仍有配准良好的工程原型，需要后续统一手绘笔触。技能图标候选也不等于完整 UI 美术系列完成。
- 资产管线有 5 项自动测试，覆盖增量同步、历史保留、未知候选隔离、透明留边与脚底锚点、Phaser 图集别名、只读检查、确定性生成、本地快照回退、缺失失败及图集尺寸约束。
- 本页不沿用旧版本性能成绩。每项证据关联其实际受测构建，以下分别记录最终整合包与此前同一美术实现的检查。真人盲测、趣味与复玩判断独立记录，技术验证不直接证明孵化或商业价值。

## 最终性能、内存与离线交付

冻结包通过 600.233 秒有效模拟时间的独占压力采集，标准/低特效经真实暂停菜单切换，各约 300 秒；准备及暖机不计入这十分钟。场景通过真实 DOM 操作建立：清除首感染源、处理裂殖精英、阻断迁移、装备免疫灯塔，保留两个仍按正常生命值与开放通路产兵的感染源。两档均保存了 24 个活敌与 3 只免疫细胞共存的快照，采样中观察到至少 940 个不同的近期有效咬击事件。敌人会实际死亡、再生成，细胞也会到期；这不表示每一帧都恒定为 24+3。

| 特效档位 | 实际帧数 | 平均 FPS | p95 帧间隔 | 最大帧间隔 |
|---|---:|---:|---:|---:|
| 标准 | 18,004 | 60.001 | 16.8 ms | 17.1 ms |
| 低 | 18,009 | 60.001 | 16.8 ms | 17.5 ms |

采集设备为 Windows 10.0.26200、i7-10700K、16 逻辑核心、约 64 GiB 内存，Chrome 155.0.8059.85 无头模式，1366×768 离线入口；结果只覆盖该设备与场景，不外推为低端机或手机成绩。页面错误、远端请求与观察器丢帧均为零，受测 `game.js` 全程未变化。原始记录为 `artifacts/art-v080/performance/report.json` 和 `frame-times.json`，标准/低特效的实机截图在同目录。

自然内存共有 116 次 CDP 采样，未插入强制 GC。V8 已用堆在约 10.44–36.61 MiB 之间波动；完整分钟中位数与采样最低值均非单调增长。后段第 1–2 分钟与最后完整分钟相比，已用堆采样最低值下降 5,286,800 字节；这些最低值不是 GC 后活对象底线。V8 预留容量有所增长，embedder 与 backing storage 另列于报告，不能把预留容量当成已用内存。

十分钟结束后，单独执行返回菜单与 10 次真实开局/Q/暂停/返回菜单，并在检查点强制回收。首次菜单与第 10 次重开后的已用堆分别为 8,873,056 / 8,885,464 字节，相差 +12,408 字节；DOM 节点 523→524，监听器保持 71。中间第 5 次的堆和节点也有单独记录。这支持本次有限窗口内未出现逐批增长的菜单保留现象；未测量浏览器总 RSS、原生 Canvas/WebGL 表面、显存或压力期间 Phaser 纹理/精灵池计数，不作完整原生内存或无限期无泄漏结论。分析及趋势图为 `memory-review.json`、`heap-trend.svg`。
