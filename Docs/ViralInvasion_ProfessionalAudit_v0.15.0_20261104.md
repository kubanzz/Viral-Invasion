# v0.15.0 专业自检：从功能完成到参赛体验

日期：2026-11-04。目标：围绕“万物生”参赛，争取获奖与后续孵化，同时满足玩家此前提出的清晰争夺、守线压力、军团接防、智能病毒、弹射建设和营地成长。

后续实施：本报告保留v0.15.0审查时的结论。其优先文案、HUD、接防反馈、Boss远程反制、奖励揭示与营地试枪建议已在[v0.15.1体验优化](ViralInvasion_Experience_v0.15.1.md)落实；真实新玩家与实体手机目标继续待验。

本次为只读审查：主会话和三路独立审查共同核对冻结 candidate-3 源码、桌面／触控／掉落补充三份真实整局记录，以及已发布实战截图。没有修改玩法、数值或冻结发行包。浏览器工具拒绝打开本地 file 协议，本次没有新增手动试玩；既有自动整局与真实新玩家观察分别记录。三份主要记录使用同一 seed71，不能当作跨种子平衡或新手留存样本。

## 总体判断

当前已经是可参赛的完整原型：七区双线、真实军团接防、施工与弹射、特殊敌人、Boss、奖励带回和营地再出击构成完整闭环；奇幻体内生态画法连贯，离线与资源预算有凭证。现有17项联验支持功能和发行可靠性。

以获奖和孵化为目标，建议继续打磨后再定稿。当前最大风险是首次试玩的信息理解、核心机制的可见收益、Boss高潮和奖励揭示。测试脚本预先知道按键、路线、目标及菜单位置，因此完成自动整局不能证明新玩家会发现这些内容。

最值得保留并放大的作品定位是：**在巨人体内夺回生命组织，让免疫军团接管防线，把感染战场变成安全营地。** 这将“万物生”与玩家行动连接，也能把本作与一般移动射击区分开。下一轮优先让玩家真实经历“我终于把一条线交给军团，可以放心出击”的时刻。

比赛未提供完整权重、其他参赛作品或评审结果，本审查不估算获奖概率。

## 优先发现与最小改进

P1表示建议在正式开放评审试玩前处理；P2表示应在核心体验验证后推进。本轮未确认新增的阻断通关、奖励重复或永久进度丢失缺陷。

### P1-1：部分现行提示仍然教错操作和受袭位置

**确定缺陷。** 第三波提示仍可能出现“朝它Q部署细胞”；配装详情明确写准星指敌／空地部署；免疫强化正文保留“瞄准十字组织”和随机阶数解锁驻防的旧说法。当前挑战已经是脚下Q、满两团调最近团，且基础驻防直接可用。

此外，前线与生命泉都会发出争夺事件，事件消息却统一称“生命泉正在被侵染／失守”。普通贴泉污染也不能统一要求寻找带标记侵染者。玩家据此回防可能找错地点。

证据：`src/game/endless.ts:276`、`src/ui/growthHud.ts:51`、`src/game/endlessGrowth.ts:90`、`src/game/session.ts:1289`、`src/game/territory.ts:525`。现有 `src/ui/endlessTutorial.ts:25` 已有正确的territory分支，旧战役说明应保留在旧模式内。

最小改进：为挑战统一生成操作说明；事件提示直接读取实际节点名与污染者类型。示例：“北前线正在侵染42%：拦截标记侵染者”“南生命泉正在污染：清除泉边病毒”。所有挑战Q统一为“走到地点，按Q脚下驻军；满两团时调最近团”。

### P1-2：战场阅读负担仍偏重，手机按钮命名存在歧义

**截图事实＋理解风险。** 桌面同时常驻多组波次、构筑、辅助、导航与技能面板；手机战斗中长期标签、反制术语和顶部多行目标争夺注意力，部分正文仅9—10px。标签避让和48px点击区检查解决各自问题，但还需验证玩家能否迅速读懂战场。

手机最大攻击盘叫“净化”，旁边夺点动作叫“附近净化”。用户此前已经问过“我该怎么净化”，这组命名会让首次玩家难以凭按钮判断射击和夺点的区别。

证据：发布 `Gameplay.png`、`Construction.png`；`src/ui/mobileHud.ts:29`、`:254`、`:286`；`src/ui/territory.css:30`；`src/render/expeditionVisuals.ts:26`；`src/render/sceneLabels.ts:155`。

最小改进：大盘改“射击”，夺点动作改“净化组织”，心核动作按上下文显示“修复心核”。默认信息收敛为玩家／心核耐久、双线状态、一个下一步；构筑、连击与详尽规则移入详情。长期对象使用图形和短名，完整说明只给当前目标、正在交互对象和即将造成伤害的危险。

### P1-3：军团接防容易被理解成隐形考试

**现行规则事实＋体验假设。** 交接验证在进攻小队出生时检查驻军是否已有两名到位；途中才到位的军团不能验证这一队。若玩家先击杀侵染者、军团尚未真实命中，当前验证也不成立。规则能防止虚假交接，但玩家可能感觉“我明明守住了，为什么不算”。

证据：`src/game/territory.ts:87`、`:110`、`:161`，`src/ui/territoryHud.ts:94`。III阶到双线交接之间的记录包含赶路、净化和战斗，不能全部算成无事等待。

最小改进：前线显示短证明链：“驻军到位2/2 → 等待反扑 → 军团已拦截 → 清除剩余护卫 → 接管完成”；失败立即给原因和下一步。完成时用旗标／稳定脉络和一句“北线已接管，可以反攻”表达收益。是否允许途中到位后接入当前小队，应作为明确的规则调整单独验证。

### P1-4：Boss目前存在压轴乏力和远程安全带风险

**实际记录＋代码支持的平衡风险。** 三份记录中，Boss从开战到死亡分别约10.08、14.65、18.23秒，均未出现Boss开战后的 `PLAYER_HURT` 事件。它们是熟练自动操作，不能据此断言新玩家同样容易。

晶壳Boss扫击射程330、二相扩张脉冲外缘380，普通主弹射程530；晶壳分支存在能正常输出却位于这两类危险之外的距离带。Boss阶段还会停止普通波次并先清空此前敌人，前面的双线压力随阶段切换下降。

证据：`src/game/motherCore.ts:10`、`:21`、`:36`，`src/game/playerProjectiles.ts:13`，`src/game/session.ts:1340`，`src/game/endless.ts:180`；三份自然报告的 `CORE_COMBAT_STARTED/CORE_CLEARED`。

最小改进：先让Boss对常用射击距离产生明确、有反制的威胁，例如更远的脉冲覆盖与清晰安全缺口，使玩家需要改变站位；再按实测校准击杀时间。保留攻击后恢复窗口和提前击杀能力。单纯增加耐久会延长现有安全输出，不足以解决这个问题。

祭团同样需要验证“迫使玩家转移优先级”：三祭司在三次记录中约4.47／8.68／4.50秒内被清除，实际发射1／4／1枚追踪弹，触控路线吃到一次35伤追踪命中。优先增强第一轮充能、施法来源与护膜依赖的可读性，再决定阵位与首发节奏；高输出提前剿灭仍应是有效反制。

### P1-5：正常通关的奖励高潮被结算覆盖

**已证实的表现缺口，奖励没有丢失。** 桌面和触控主流程中，Boss掉落与胜利分别同在tick8564／14733发生，创建战利品后同帧自动收齐并暂停结算。胜利页只泛称“战利品已带回”，没有展示本次枪型、品质、蓝图与材料。补充演示有意保留真实幼体，才拍到落地袋子，这并非普通玩家必然经历的流程。

证据：`src/game/session.ts:1356`、`:1369`，`src/ui/territoryHud.ts:163`；`natural-desktop-final-5`、`natural-touch-final-3`、`natural-loot-final`。

最小改进：保留立即保存，在胜利页直接给可跳过的奖励揭示卡：紫／金品质、贯脉针枪用途、速装蓝图、40生质；主操作可以直达修复该武器。玩家无需故意留下残敌或等固定时间才能看见奖励。

### P2-1：施工完成了，但发现率和战术收益还缺证据

**源码事实＋验证缺口。** 蓝图解锁成功后主要执行保存，手机建造位于战术折叠菜单，缺少一次明确的“新蓝图可用”反馈和首次建设提示。现有三次自动路线都预先知道B键和合适选址。

三次完整流程各发射一次弹射荚，落点冲击均为0命中／0伤害。这证明施工与弹射流程可用，尚未证明“救泉回防、落地清大片”的实际价值。自动操作选了安全演示落点，不能据此判断炮台无用。

证据：`src/main.ts:253`、`src/ui/mobileHud.ts:24`、`src/ui/endlessTutorial.ts:26`、`src/ui/endlessHud.ts:263`；三个 `TERRITORY_CANNON_EXPLODED` 事件。

最小改进：首次守线提示获得蓝图并高亮入口；有军团与短安全窗口时，引导一次自主选址施工。试玩观察玩家是否主动利用弹射拦截另一线，并在装填后再次使用。建筑继续作为有价值的选择，不增加“必须发炮才可赢”的额外通关条件。

### P2-2：营地闭环成立，武器身份和再次出击目标仍偏弱

**内容范围事实＋待真人验证的体验。** 两种枪和两种蓝图足以验证首版；首通已经获得全部蓝图，每胜40生质及重复蓝图转化，使有限三级强化很快接近上限。二次出击目前主要换种子和抽品质。

稳流枪34伤、单体；紫贯脉29.68伤、两体，强化一级后30.52。横向取舍本身合理，但共用持枪图和主弹表现，可能让玩家只看见“紫枪伤害更低”。首次回营的修复与装备还分在两个页面。

证据：`src/game/expedition.ts:12`、`:38`，`src/meta/campProfile.ts:151`、`:170`，`src/game/playerProjectiles.ts:73`，`src/render/phaserRenderer.ts:377`，`src/ui/campHud.ts:26`。

最小改进：优先补贯穿命中的特征反馈、按用途比较和双靶试枪；首次回营用可跳过的“修复→装备→试射→再出击”短引导。之后再考虑少量心脏委托和横向挑战，先不扩大器官、材料和装备系统。

## 建议执行顺序

1. **首次试玩打磨：** 统一真实操作文案与节点名称，区分射击／组织净化，收敛HUD，补蓝图入口和接防过程反馈。
2. **高潮与收益打磨：** Boss远程反制和二相站位变化，祭团首轮威胁表达，胜利奖励揭示与回营直达修复。
3. **复玩验证：** 贯穿武器试射与特性反馈，观察弹射是否产生主动回防选择，再按数据决定心脏委托；地图、画法和核心军团规则继续保留。

本轮建议不直接统一提高生命、伤害或出怪数。先让玩家理解规则，才能分清“战斗确实太简单”和“不知道该做什么”的不同原因。

## 开放评审试玩前的验证目标

以下是建议验收目标，尚非已取得结果：

- 5名未接触项目的玩家，至少4名在3秒内指认正在受袭的一线，第一次靠近能选对组织净化动作。
- 至少4名首次守线后能发现并开始建设，能够解释军团接管完成与源护膜解除的关系。
- 实际观察一次弹射救泉或清群，以及玩家是否主动进行第二次使用；记录命中、回防结果和使用机会成本。
- 玩家能指出Boss要求自己改变的一次站位，并解释祭司为何值得优先击杀。允许熟练玩家无伤，观察目标是反制选择成立。
- 通关后能说出得到的武器和蓝图，完成修复、装备并试射；至少3名自发选择再次出击。
- 首局5—8分钟、实体手机多指／音频／安全区／后台恢复分别实测。熟练脚本的142.73／245.55／227.02秒不能代替这些结果。

参赛展示建议用真实操作先后呈现：感染推进→玩家夺回→军团接管→出击拆源→生命复苏→安全营地。优先讲清玩家做了什么及世界怎样改变；减少菜单、参数表和系统数量展示。
