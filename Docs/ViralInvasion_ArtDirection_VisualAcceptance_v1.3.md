# Viral Invasion：视觉设计与美术验收规范（Art Direction Bible）

> **v1.3 · 2026-10-26 · 正式项目决策**  
> 关联：`ViralInvasion_GDD_v1.3.md`、`ViralInvasion_Codex_Development_Acceptance_v1.3.md`  
> 适用范围：从零开发的独立《Viral Invasion（病毒入侵）》；**不是原心脏巡游项目的素材移植方案**。  
> 本文为**目标美术规范和验收基线**，不是已实现作品的证明。参考图只用于理解意图；游戏内美术应为原创或合法授权资源。

## 1. 已确认的视觉决定（优先级高）

| 项目 | 决定 | 严禁误解为 |
|---|---|---|
| 摄像视角 | **3/4 斜俯视、伪 2.5D 手绘场景**：角色可见头顶及正面/侧面，有生物腔体的纵深层次 | 纯正上方 90° 俯视、横版侧视、等距菱形网格、真 3D 镜头 |
| 操作与玩法空间 | **二维平面自由移动（WASD + 360° 瞄准）**，碰撞/路径/技能范围在同一逻辑平面 | 横版跳跃、重力平台、三维 Z 轴跳跃或 3D 碰撞 |
| 基础美术 | **手绘 2D 生物幻想**：柔和笔触、有机边界、腔体/细胞/血管层次；角色和病毒有童话式生命感 | 纯几何方块、写实血腥器官、过度光滑的 3D 玩具渲染 |
| 光效 | **适度霓虹生物朋克**：发光只服务交互、能量、诊断及病理状态 | 全屏高亮 Bloom、把所有组织画成炫光管线 |
| 风格优先级 | **手绘质感 > 器官氛围 > 战斗辨识度与形态语言 > 特效密度**；实际战斗时辨识度拥有最终否决权 | 静态概念图漂亮就算通过 |
| 目标设备 | 桌面浏览器、Canvas 2D + 分层精灵/图层，开发期可以程序占位 | 必须上 3D 引擎、着色器或外部在线素材服务 |

**视觉关键词**：显微童话、活体迷宫、绘本式器官腔体、鲜艳而克制的生物荧光、亲和但危险的异变生物。情绪定位为“奇异、紧张、有发现感”，而不是重口恐怖。

## 2. 相机、坐标系和空间呈现（必须在 M02 冻结）

### 2.1 物理坐标不能依赖绘制的高度错觉

- 逻辑层使用二维世界坐标 `world(x, y)`；移动、敌人 AI、路径图、碰撞、鼠标瞄准、治疗范围都基于同一套世界坐标和碰撞形状。
- 建议的最低成本方式是**屏幕 XY 仍对应逻辑 XY**，让角色以 **3/4 手绘造型、非对称阴影、遮挡、透视化环境插画**营造斜俯视，而不是硬套旋转/等距投影。若采用非等比屏幕变换（如压缩屏幕 Y），输入与命中必须走同一个可逆变换，不能出现视觉上击中却判定没击中的情况。
- 角色脚底（或接地锚点）决定世界位置、Y 排序与碰撞；头部、触角、立体组织/设施仅是高于脚底的绘制内容，不额外加入不可见的第三维操作。
- 不允许因为美术变化私自加入跳跃、平台重力或高低台关卡门槛。斜坡/立体桥可以是美术错觉，但是否通行由明确的 2D 路径与碰撞多边形决定。
- 玩家全方向移动；角色可以采用 4/8 向贴图、骨骼拼接或程序化朝向，**枪口朝向、鼠标瞄准和子弹判定一致**。

### 2.2 建议的图层顺序（稳定且可测试）

1. **远景氛围层**：器官深处、模糊组织、缓慢粒子；与交互无碰撞。
2. **地形基底层**：可走面、血流/气流方向、感染纹理与可交互节点的底部提示。
3. **接地阴影层**：角色、感染体、掉落物的柔和接地阴影（与脚底同步）。
4. **世界实体层**：按接地锚点 `worldY` 进行稳定 Y 排序，绘制角色、敌人、设施、矮障碍。
5. **前景组织层**：血管弯壁、膜瓣、细胞簇；遮挡实体时可局部降透明度或描出轮廓。
6. **特效/警示层**：命中、范围预警、抗体连锁、心跳/气流；危险判定范围必须可见。
7. **固定 HUD 层**：血量、器官状态、目标与研究/进化提示，不受摄像机位置影响。

**遮挡原则**：遮挡可以营造器官层次，却不得长期遮住玩家、重要病毒弱点或交互设施。进入遮挡区时角色轮廓/底部圆环应继续可辨认；前景组织按规则半透明或动态裁切。阴影仅辅助定位，不得误导碰撞。

### 2.3 摄像机与场景镜头

- 首版镜头跟随玩家，保持战斗视野稳定；可有受击轻微震动与冲流强调，避免频繁大幅缩放/摇晃。
- G0 只要求一屏训练场和基础跟随/变换；G1 再完成生物环境层次和前景遮挡；G3 肺部沿用同一摄像机/碰撞规范。
- 初始适配 16:9 桌面，至少覆盖 1366×768 和 1920×1080、DPR 1/2。缩放时采用逻辑像素与 CSS 像素分离的统一适配策略。
- 最佳视野不是表现角色细节最大，而是能看清玩家周围敌人的运动、脉冲窗口与治疗目标。

## 3. 统一造型语言

### 3.1 玩家（医疗战士）

- **白/暖白 + 青蓝**为主色，身材紧凑、可爱、富有动作表现力；可用小头盔、治疗背包和荧光扫描件形成统一识别。
- 在实机战斗缩放下，仍能通过**轮廓、姿态、底部定位环**识别玩家；不依靠头盔极小纹理识别职业。
- 最小 G0 动画要求：待机、移动、攻击、扫描、治疗、受击、冲刺（临时程序绘制可替代正式逐帧图）；到 G4 再打磨动画过渡和细节。

### 3.2 病毒族群（童话化，但不可降低危险辨识）

| 类型 | 必须可辨识的形态 | 进化后变化方式 | 动作和预警 |
|---|---|---|---|
| 普通病毒 | 圆形/软弹体、明显核与短突起 | 尺寸和行动节奏变化，但保留基本轮廓 | 接近前的眼神/壳体方向/冲刺预备 |
| `CARAPACE` 晶壳 | 不规则结晶片、厚壳的缺口和核心 | 结晶增生、破甲时碎裂露核 | 破绽方向以形状/闪烁而非单靠颜色表达 |
| `FISSION` 裂殖 | 分瓣或多核、母体有分裂纹 | 分裂时爆开为数量有限的小体 | 裂变倒数、分裂方向与落点预警 |
| `MIMIC` 潜伏 | 软膜和半透明组织拟态 | 活动时逐渐显影、恢复轮廓 | 仍保留周期性波纹/微扰，Q 扫描可见 |
| 迁移感染体 | 细长、偏流线型形体 | 可转化为穿越器官通道的状态 | 地图路径、出入口高亮和迁移倒计时 |

- 三种病毒缩为相同大小的黑色剪影时，也应靠突起/碎裂纹/流线尾部区分（可用程序化黑白截图测试）。
- 不以颜色为唯一识别；危险与弱点都同时使用形态、描边、动作前摇或图标。
- 普通型可显得可爱；进化型通过不对称晶壳、分瓣、多眼或触手突出威胁，避免纯写实恐怖。

## 4. 器官美术语言：同一世界，不同物理机制

| 维度 | 心脏战场 | 肺部战场 |
|---|---|---|
| 主色调 | 深酒红、绯红、洋红、暖金 | 蓝绿、青蓝、珍珠白、淡粉紫 |
| 场景结构 | 弯曲血管、瓣膜、肌理层叠、血流河道 | 分岔气道、肺泡群、半透明膜与气流通路 |
| 常态动态 | 温和组织搏动、方向性流光、红细胞流动 | 呼吸扩张/回落、气泡漂移、方向性雾/气流 |
| 核心战场信号 | 心跳相位、冲流扇区、晶壳破绽 | 吸气/呼气相位、推动方向、气道开闭 |
| 危险可读性 | 危险扇区暖色边线 + 节律图案 + 倒数 | 气流箭头 + 通道边框 + 抵达位置预告 |
| 背景亮度 | 环境主体压暗，交互节点以暖色提亮 | 背景可以偏明，但玩家/病毒边缘仍须形成反差 |

| 玩家主体/医疗 | `#F1F4EA` / `#46DFF5` / `#146A98` |
| 病毒/感染 | `#D72B67` / `#FF7058` / `#EDAD3C` |

| 肺部 | `#163E59` / `#2389A6` / `#73DDE0` / `#E8DBF1` |

**心肺差异不是简单换滤镜**：器官背景、流向、可交互设施外形和环境动态要共同区别，并与 M10/M11 的实际机制一一对应。

## 5. 抗体特效与信息层级

| 效果 | 视觉标识 | 真实规则约束 |
|---|---|---|
| 扫描 Q | 青色扩散圆环、短暂显影轮廓 | 有实际扫描范围；线框不误导成伤害区 |
| 精确净化 | 短促 Y 型抗体弹与浅青命中火花 | 轨迹/碰撞/射程吻合；不可用满屏粒子隐藏弹道 |
| 范围裂解 | 放射型/环形扩散，边缘清晰 | 判定半径和作用时间能被玩家预估 |
| 组织修复 | 柔和青绿修复粒子，组织结构回填 | 治疗量与组织表现一致；对敌人无效清晰可见 |
| 心跳冲流 | 暖金脉冲弧线 + 流向箭头 | 预告方向/扇区与击退和破甲判定一致 |
| 肺部气流 | 青白弧线/气流带 + 速度方向 | 推动与判定方向一致，错误封锁有可读提示 |
| 病毒进化 | 形态重组、8 秒预兆、特性图标 | 不只换色；弱点/代价同屏或可回看 |

- 最高视觉优先级：**玩家位置 → 致命危险 → 病毒弱点/当前目标 → 关键效果 → 场景氛围**。非关键动态组织必须为前四项让位。
- 建议同时保留“低特效”开关（G4）：缩减背景粒子、Bloom 和屏幕震动，不削弱碰撞预警及必要判定提示。
- 同屏压力目标以实际设备为准：性能不足时**先减少装饰粒子、降低后处理**，不要悄悄移除敌人或改变病毒规则。

## 6. HUD / UI 基础规范

- **左上**：玩家耐久 + 当前工具 + 必要状态；**右上**：器官简图/进化预警/当前目标；**下方边缘**：器官健康、抗体槽位及充能提示。布局应为建议，不允许占据射击与躲避的核心视野。
- 面板造型：低透明深色底、细青蓝发光边、适当圆角与有机曲线；**不要**让所有 HUD 都变成巨大的高亮霓虹牌。
- 标识分工：玩家/主动净化青蓝；病毒/敌方伤害珊瑚红；器官环境以各器官色板区分；高危险同时使用轮廓、计时与方向。
- 战斗内信息必须能用短句理解（如“晶壳：心跳后破绽 3 秒”），避免信息被浮动伤害数字淹没。
- 暂停/研究面板可以有细节，实时战斗 HUD 以即时辨识为先。

## 7. 素材与实现建议：不要求 Codex 从第一天复刻概念图

### 分三层交付，不能只做漂亮示意图

1. **G0｜风格占位**：先画能证明空间与操作的心脏训练场，至少区分远景、有机地形、玩家/病毒、前景组织和 HUD；程序化几何可用，但比例、配色、斜俯视轮廓与投影/碰撞必须正确。无需高精场景贴图。
2. **G1–G2｜可玩的风格垂直切片**：加入有手绘感的组织/血管纹理与精灵表现（可用自己绘制的程序化有机纹、Canvas path、或合法素材）；至少 3 种病毒剪影、进化前后形态、心跳冲流及抗体连锁可读。记录同屏压力截图。
3. **G3–G4｜双器官一致性与品质**：同一角色/病毒风格迁移至肺部，新增肺泡/气流/薄膜层；优化材质、动画、可读性和帧率，再考虑宣传级细节。

建议资产可为独立 PNG/WebP 精灵、轻量图集与可编辑的 SVG/Canvas path 素材；**源文件和可复用的绘制逻辑都必须存于新仓库**。如果图片较大，打包离线包时应对资源大小和加载做预算。不得默认用聊天里的第三方游戏截图当作游戏贴图，也不得擅自把参考图描摹成可交付商业素材。

## 8. 美术/视角验收清单（`VIS-01` 至 `VIS-12`）

| ID | 阶段 | 可检查的通过标准 | 证据 |
|---|---|---|---|
| `VIS-01` | G0 | 画面能辨别为**斜俯视的 2D 自由移动战场**；角色显露头顶/正侧面，至少有近景与远景深度，而非横版平台或纯顶视平面 | 实机全屏截图 + 短视频 |
| `VIS-02` | G0 | WASD 八向/斜向移动与鼠标 360° 瞄准有效；不依赖跳跃/重力/Z 轴；镜头表现变化不改变物理规则 | 同一路线输入与位置/命中日志 |
| `VIS-03` | G0 | 三种窗口/DPR 条件下，画面角色枪口、鼠标准星、弹道与实际命中对齐；若有 XY 投影必须覆盖逆变换测试 | 自动化鼠标/投影测试+截图 |
| `VIS-04` | G0 | 角色/敌人按接地 Y 排序，头顶可超出脚底排序界；前景遮挡时不会不可见或造成误导碰撞 | 重叠与遮挡边界测试图 |
| `VIS-05` | G1 | 玩家、普通体、晶壳/裂殖/潜伏的**黑白剪影**在实战缩放下可区分，并与进化规则对应 | 等比例剪影对比图 |
| `VIS-06` | G1 | 心脏搏动、流向、阀门/冲流范围提示在战斗中看得见；示意预览与实际影响范围相符 | 录屏与规则断言 |
| `VIS-07` | G1–G2 | 危险、弱点、扫描与治疗至少两种非颜色信号；高光和粒子不过度盖住关键角色/预警 | 常规与密集战斗截图 |
| `VIS-08` | G2 | 病毒进化前/预警/进化后，玩家能在实机画面辨识能力变化和对应反制，不只显示数值改变 | 同场景三状态截图/录屏 |
| `VIS-09` | G3 | 不看器官名称也能通过**心脏：瓣膜/血流/脉冲，肺部：肺泡/气道/气流**区分场景，且其特性影响实际玩法 | 心肺同等缩放截图 + 交互录屏 |
| `VIS-10` | G4 | 实时 HUD 在 1366×768 与 1920×1080 下不遮挡关键可射击区域，缩放后布局/提示可读 | 多分辨率截图 |
| `VIS-11` | G4 | 普通/低特效模式下的伤害与碰撞判定一致，低特效仍显示所有致命警示；压力战斗满足 M16 帧率预算 | 同 seed 对比 + 帧率报告 |
| `VIS-12` | G4 | 至少 5 位首玩者观察：能认出玩家、至少两类病毒与正在生效的器官危险；逐条记录未认出的情况，不得编造主观分数 | 盲测观察表 |

**验收方式**：将 `VIS-*` 状态追踪到配套验收矩阵；机器测试与真人观察分别注明。概念图不能替代实际游戏截图，手绘精度不足可列为美术债，但视角错误、输入误判、遮挡造成游戏不可玩不能列作“以后优化”。

## 9. 给 Codex 的美术执行红线

- 始终使用**斜俯视伪 2.5D + 2D 平面物理**；不要自行换成横版平台、等距菱形寻路或真 3D。
- 优先保证一眼能看清当前危机、角色和病毒行为，再增加荧光与组织细节。
- G0 要有简化但正确的透视/深度原型；不能因为概念图难画就永久退回纯圆点俯视界面。
- 所有截图都必须注明是**概念目标图**还是**真实游戏运行画面**；两者不得混称。
- 美术变化不要破坏 M00–M16 的双向进化、抗体联动、器官策略和离线功能。


## 10. G0 实施登记 · 2026-10-26
