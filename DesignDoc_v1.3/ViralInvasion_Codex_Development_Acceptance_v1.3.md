## 0. 总执行规则（优先级高于每个具体模块）

1. **仅在新项目目录工作**：默认在用户提供或新建的独立空目录初始化 Git 仓库；不得扫描、修改、覆盖或引用原“心脏巡游”工程的源码、素材、存档或本机路径。若目录非空，先列出冲突文件并做安全保护。
2. **不是双模式项目**：只构建《Viral Invasion（病毒入侵）》一个游戏入口，不增加经典心脏巡游、LegacyAdapter、模式切换，也不承担旧项目回归。
3. **分阶段提交**：每阶段完成时列出实际新增/修改文件、浏览器实测证据、自动测试结果、未解决问题；不得所有模块一次写完再测试。
4. **三层证据分开**：代码单测、浏览器真实输入、真人试玩必须分别报告；自动化通关不能证明游戏好玩。不能执行时列明阻塞与手动步骤。
5. **已确认工程栈（2026-10-27 修订）**：TypeScript + Phaser 开源框架；Krita 制作美术与逐帧动画；Vite 本地开发，Vitest 单元测试，Playwright 浏览器测试，esbuild 输出 classic/IIFE 发行脚本。素材根目录沿用 `asserts/`，不要求付费编辑器。当前原生 Canvas 实现待迁移；须先证明图集加载、离线兼容及维护成本可控，再扩大迁移。
6. **离线交付必须实际验证**：开发期允许本地 Node/npm 工具；发行包 `dist/index.html` 及相对路径静态资源不依赖 CDN 或远程脚本。必须验证断网与 `file://` 打开 Chrome/Edge；不能把 Vite 默认 ESM 产物直接声称支持 `file://`。可采用经典脚本 IIFE、内联脚本或其他经过验证的方案。
7. **数据驱动、确定性优先**：病毒特性、抗体、阶段、器官集中配置；引擎采用固定模拟时钟、可复现 seed、明确的事件顺序；不得散落魔法数字。
8. **工程从零可复现**：提交 `package.json`、锁文件、`README.md`、`.gitignore`、必要测试和构建脚本；在干净工作区执行 `npm ci`、`npm run build`、`npm test` 并记录结果。
9. **架空医疗**：将病毒、抗体和器官机制视作幻想游戏规则，不加入真实病原操作步骤或真实疗法推荐。
10. **没有用户授权，不引入旧资产**；如果后期确需借鉴原项目，先提交独立提案。当前阶段不得以“移植旧代码”为默认捷径。
11. **已确定美术/空间规范**：3/4 斜俯视伪 2.5D + 手绘生物幻想 + 适度霓虹；保留 2D XY 玩法平面，WASD 全方向移动和鼠标 360° 瞄准。不得做成横版跳台、纯顶视、真 3D 或需 Z 轴跳跃的关卡。
12. **美术规范文档具有执行效力**：`ViralInvasion_ArtDirection_VisualAcceptance_v1.3.md` 的图层、坐标、病毒剪影、心肺视觉和 `VIS-01`–`VIS-12` 逐阶段验收；G0 做正确的低保真视觉基础，不要求第一轮重绘精美成品。

## 1. 建议的目标架构与目录（独立项目）

**命名约束**：仓库/目录示例 `Viral-Invasion/`，`package.json` 的 `name` 为 `viral-invasion`，HTML `<title>` 和游戏可见标题统一为 `Viral Invasion`；存档 key 建议 `viral-invasion:<schema-version>:<key>`，会话 `game` 为 `viral-invasion`。这是新项目，不需要对旧品牌做兼容迁移。

```text
Viral-Invasion/               # 新建仓库，不能位于旧项目内部
├── index.html                            # 开发入口
├── package.json / package-lock.json
├── vite.config.ts                        # 本地开发（非最终 file:// 发行约束）
├── scripts/build-offline.mjs             # 生成 classic/IIFE 离线发行包
├── src/
│   ├── main.ts                           # 新游戏单入口（菜单/开始/暂停/重开）
│   ├── core/{clock,rng,events,session}.ts
│   ├── input/{controller,bindings}.ts
│   ├── render/{phaser,camera,depthSort,occlusion,layers,effects}.ts
│   ├── actors/{player,virus,collision}.ts
│   ├── organs/{graph,heart,lung}.ts
│   ├── systems/{infection,evolution,pressure}.ts
│   ├── systems/{therapy,protocol,progression}.ts
│   ├── systems/{migration,encounter}.ts
│   ├── ui/{hud,menus,feedback}.ts
│   ├── save/{repository,schema}.ts
│   └── content/{organs,traits,protocols,balance}.ts
├── tests/{unit,integration,e2e}/
├── Docs/                                  # GDD、验收矩阵、试玩记录
├── asserts/                              # 沿用已有素材根目录；按批次保存 .kra、PNG 帧序列与图集
└── dist/                                  # 构建产物，不提交到 Git 默认跟踪
```

目录为建议分层；Codex 可合并文件，但必须保留测试边界与清晰职责。

**视觉与物理关系**：物理世界为 2D XY；角色接地锚点是碰撞/Y 深度排序基准；3/4 手绘外形、组织高度和阴影只改变屏幕显示，不引入第三维碰撞或横版重力。渲染建议 `远景 → 地形 → 接地阴影 → 世界实体(Y排序) → 前景遮挡 → 特效/警示 → HUD`；若采用屏幕 XY 非等比缩放，鼠标命中走镜头的逆变换并做多分辨率回归。详情见 Art Direction Bible。

**逻辑关系**：`GameHost → SessionController → Clock/RNG/EventLog`；单独的输入、Phaser 表现与确定性碰撞模块；器官节点图、病毒、进化、压力、治疗、抗体、成长、迁移、关卡阶段、UI 和存档模块通过显式事件连接。**不包含 ModeRouter / LegacyAdapter / TherapyAdapter（旧模式适配）**；从零实现 `TherapySystem`。

**打包约束**：`npm run dev` 启动本地开发服务；`npm run build` 执行正式离线构建，产物 `dist/index.html`、`dist/game.js`（classic script，可调整为单 HTML）。严禁把 `type="module"` 的 Vite 默认构建视为已满足 Chrome 的 `file://` 使用要求；必须跑浏览器实际验证。`dist` 所需素材一并本地打包。

GameSession = {

### 1.2 事件契约

建议至少统一以下游戏事件；事件可以通过日志回放或测试断言检查：

| 事件名 | 关键字段 | 为什么需要 |
|---|---|---|
| `RUN_STARTED` | seed, mode, startAtTick | 可复现启动 |
| `INFECTION_SOURCE_CLEARED` | organId, nodeId, actor | 验证目标、XP 和传播停止 |
| `ORGAN_INTEGRITY_CHANGED` | organId, before, after, reason | 追踪组织损伤与治疗 |
| `VIRUS_EVOLUTION_WARNING` | traitId, organId, warningUntilTick, counterHint | 预警与 UI |
| `VIRUS_TRAIT_APPLIED` | traitId, organismId, tick | 进化真的生效 |
| `PROTOCOL_OFFERED` | poolIds, choices, reason | 公平性、草案回放 |
| `PROTOCOL_EQUIPPED` | protocolId, replacedId | 装备槽上限 |
| `SYNERGY_TRIGGERED` | synergyId, targetCount | 可见的组合收益 |
| `MIGRATION_WARNING` | from, to, deadlineTick | 迁徙预警 |
| `MIGRATION_RESOLVED` | decision, from, to, consequence | 行为影响后续局势 |
| `RUN_ENDED` | success, reason, seed, durationSimMs | 可解释结算 |

统一事件字段来源：模拟状态，不能 UI 在结算时推测；所有高频事件可做聚合统计，防止日志过大。

## 3. 工作包定义（每个模块均需可独立验收）

### M00｜独立仓库初始化与运行基线 · P0 · 依赖：无

**开发任务**：在全新目录建立 Git 仓库、TypeScript + Phaser 工程、npm 锁文件、构建与测试脚本、文档、基础 CI 可选配置；创建可独立运行的欢迎画面与第一份 Git 基线。除非用户另行指定，禁止读取/迁移旧游戏资产。

**交付物**：新项目目录树、README（开发/构建/离线运行）、Git 提交标识、独立工程启动与打包证据。

- `AC-M00-01`：核实仓库名、npm 包名、HTML 标题、游戏 UI 和新存档前缀均采用 Viral Invasion；新目录含 `package.json`、锁文件、`src/`、`tests/`、`Docs/`、`.gitignore` 与 README；能说明源码与 `dist` 的关系，并记录真实 Git 提交/哈希。
- `AC-M00-02`：在全新检出/干净环境能执行 `npm ci`、`npm run dev`、`npm run build`、`npm test`（E2E 待基础场景就绪），无对原仓库路径的依赖；命令、退出码、结果如实报告。
- `AC-M00-03`：静态检索构建脚本、源码和资产引用，不能指向旧“心脏巡游”本地绝对路径、旧项目文件、外网 CDN 或未经允许的资源；旧工程不存在时也能独立构建。
- `AC-M00-04`：只在新仓库执行初始化/提交；若目标目录非空先保护现有文件，不覆盖未知或未提交内容；提交前清理密钥、个人路径和无关构建缓存。

### M01｜确定性模拟时钟、种子、事件总线 · P0 · 依赖 M00

**开发任务**：从零设计单局 Session、固定步长模拟时钟、可播种 RNG、可测试事件日志；建立开始、暂停、恢复和重新开始的状态生命周期。渲染插值不改变玩法决定。

- `AC-M01-01`：G0 用训练靶/测试规则验证：相同配置 + 相同 seed + 相同输入序列产生相同模拟状态及事件序列；G1 起把感染体出生、变异选择、伤害与结算纳入相同契约（允许非玩法相关帧渲染差异）。
- `AC-M01-02`：G0 暂停 30 秒时训练场实体、模拟时钟与事件数不推进；后台失焦恢复不一次性追赶积压帧。G1 起同样约束病毒增长/转移和感染负荷。
- `AC-M01-03`：连续执行“开局→暂停→继续→重开→新 seed 开局”，上一局敌人、事件、计时器、输入按住状态及协议状态均被正确清除。
- `AC-M01-04`：事件 payload 与字段类型可单测；重复结束调用只产生一个 `RUN_ENDED`；随机逻辑不得直接依赖 `Math.random()`。

### M02｜玩家操作、2D 渲染与训练场 · P0 · 依赖 M00–M01

**开发任务**：以固定步长驱动玩法模拟，使用 Phaser 负责画面、相机/缩放、资源和动画播放，独立处理确定性碰撞、玩家移动与冲刺、鼠标瞄准、1 精确净化、2 范围裂解、3 组织修复注射、Q 扫描、E 交互、Esc 暂停；使用**3/4 斜俯视角色和手绘风格程序占位**做单屏心脏训练场，有远景/地形/接地阴影/按脚底 Y 排序/前景层，并提供开始/重开/帮助和基础 HUD；训练目标为“净化两类靶标、修复一个组织节点、按 E 完成复测”，完成后出现训练成功界面。**地图仍是 2D XY**，没有横版跳跃/重力；不得把精美商业级图片列为 G0 硬门槛。

- `AC-M02-01`：启动后无需旧工程即可进入训练场，完成“净化靶标→修复组织→E 复测”并获得一次成功结算；暂停、继续、退出/重开有效；UI、计时与实体不会在重开后残留。
- `AC-M02-02`：移动/冲刺、1/2/3、Q、E 与鼠标瞄准在训练场有可观察、可测试结果（例如靶标受伤、组织修复、扫描信息、装置响应）；错误工具给出明确反馈。
- `AC-M02-03`：正式发行包在 Chrome/Edge 断网和 `file://` 下均可打开并玩完训练场；没有远程请求，也不会因 ES module、资源路径或 CORS 错误白屏。
- `AC-M02-04`：1366×768、1920×1080 和 DPR 1/2 下鼠标命中、渲染坐标、碰撞和 HUD 对齐；键位帮助展示实际配置；无需与任何旧版本截图保持一致。
- `AC-M02-05`：心脏训练场呈现 3/4 斜俯视视觉结构：角色能看到头顶/正侧面，场景含至少远景、地形、接地阴影、前景组织；鼠标 360° 瞄准与 WASD 八向平面移动成立，无平台跳跃/重力。
- `AC-M02-06`：角色、病毒靶标和设施按接地锚点 Y 深度正确遮挡；前景组织遮挡关键对象时可淡化或描轮廓，绝不长期遮死玩家；若屏幕非等比投影，逆变换鼠标命中可测试。

### M03｜器官与感染节点网络 · P0 · 依赖 M01–M02

**开发任务**：心脏建立感染源、组织节点与有向/可封闭连接；提供统一 `OrganState` API。初期只需要 3–6 个节点，使用本项目新绘制的血管、阀门与组织节点几何。

- `AC-M03-01`：感染源每个固定模拟间隔沿开放边扩散，关闭边后不再穿透传播，打开后按冷却恢复；地图能直观看出路径。
- `AC-M03-02`：组织健康受到真实攻击或感染下降，治疗后上升，始终 clamp 至 0–100；无负数或超上限。
- `AC-M03-03`：感染单位/节点上限和传播频率独立配置；运行 20 分钟压力模拟仍不无限分裂和卡死。

## 5. 风险、预防与取舍

| 风险 | 典型表现 | 规避/停损方式 |
|---|---|---|
| 工作范围爆炸 | 同时做四器官、全技能树、排行榜 | 强制先过 G1/G2；其余均在扩展列表 |
| 从零搭建但过度工程化 | 自研引擎或重复模拟，挤占玩法制作 | 使用 Phaser 开源组件与 Krita 逐帧流程；先过离线原型，再增量迁移表现，保留已有玩法与 DOM HUD |
| 随机进化不公平 | 病毒克制当前构筑、没有反制 | 候选合法性过滤、预警、基础工具后备、1000 seed 测试 |
| 伪差异 | “心脏/肺部”战斗打法完全一样 | 器官必须各有一种主动环境技，且验证实际改变策略 |
| 软锁 | 门被封死、无治疗资源、感染无限增殖 | 可恢复性检查、封锁有代价但可逆/可绕路、生产上限 |
| 爽感不足 | 治疗很慢、联动不可见 | 先做 G1 动作反馈和 G2 两种联动，再扩内容 |
| 数值雪崩 | 病毒越来越多造成性能或无解 | 同时活动上限、间隔产生、事件预算、危机回落窗口 |
| 用虚假测试证明好玩 | 自动脚本顺利通关即认定有趣 | 真人盲测单独验收，不允许用 AI 推演冒充 |
| 把旧工程当隐式依赖 | 构建脚本引用旧目录或旧资源，换电脑即白屏 | M00 独立依赖审计，干净检出安装、独立编译、离线实际运行 |
| 误做成横版或纯俯视 | WASD 变左右跳台，或只有二维圆点地图，器官失去纵深 | G0 固定 3/4 视角 + 2D XY 平面规则，`VIS-01`–`VIS-04` 先验收 |
| 画面炫而不清晰 | 光效掩盖敌人弱点，组织遮挡角色，攻击范围误导 | 层次/剪影/低特效对照和真人辨识测试；真实玩法截图为准 |
| 本地记录丢失 | localStorage 清理、Schema 升级或浏览器 `file://` 存储限制 | 版本化存储、可用性检测、内存降级告警、后续可做导入导出 |

## 7. 跨模块验收脚本：必须真跑的 10 条路径

1. `RUN-01` 全新安装与操作冒烟：从干净仓库 `npm ci`→构建→断网打开 `dist/index.html`→进入训练场→移动、扫描、三工具、E、暂停及重开正常。
2. `RUN-02` 新模式心脏开局：扫描、射击、治疗、组织压力、XP 和日志相匹配。
3. `RUN-03` 晶壳：预警→减伤→心跳破绽→反制成功。
4. `RUN-04` 裂殖：击败母体→有限分裂→连锁净化/范围处理→无无限复制。
5. `RUN-05` 潜伏：可通过 Q/显影发现→击杀/治疗→损伤停止。
6. `RUN-06` 协议：同局获得两个相容协议→触发联动→展示连锁事件。
7. `RUN-07` 迁移追击：警报→进入肺部→气流交互→影响新感染源。
8. `RUN-08` 迁移封锁：警报→留在心脏封锁→肺部压力低、心脏压力高→仍可获胜。
9. `RUN-09` 失败及挽回：感染到临界→抢修/净化脱离倒计时；另一次真正死亡/失控正确结算。
10. `RUN-10` 完整局：母巢具有本局特性→击败核心→器官与感染达标→主动复测→胜利，保存结果，同种子重试可复现。
11. `RUN-11` 斜俯视空间与命中：二维自由移动→经过前景组织→Y 排序切换→360° 射击/修复→缩放后坐标与命中一致，场景没有横版重力/假遮挡软锁。
12. `RUN-12` 风格与战斗可读性：同场景病毒三分支形态对照→心脏搏动及肺部气流对照→密集混战/低特效→玩家、危险、弱点和当前器官均能辨认。

所有 RUN 需要注明：自动测试、真实浏览器脚本还是真人操作，不能混写。

## 8. Definition of Done（通用交付完成定义）

模块标记为“完成”必须同时满足：

- 设计：实际规则符合 GDD，或以变更记录说明经过用户批准的调整。
- 行为：模块的 `AC-*` 有可执行测试及结果，至少包含正常和异常路径。
- 可见：玩家可感知关键因果，不仅后台数值变化。
- 稳定：不破坏已通过的**新项目阶段性能力**；状态一致，无重复奖励、无法退出或卡死。
- 可维护：新增参数集中配置，重要事件可追踪，不复制一套不可维护的主循环。
- 文档：更新操作说明、已知缺陷、必要调参解释。
- 诚实：凡未经真人试玩支持的“很好玩/愿意重玩”均只能称为假设。
